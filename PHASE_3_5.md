# 0. СНАЧАЛА — ПРОВЕРКА КАЧЕСТВА ОЦЕНКИ

**Не приступать к частям A и B, пока это не пройдено.**

Пройти диалог, отвечая нарочито плохо: односложно, без приветствия, без извинений, с отговорками («это не ко мне», «система глючит», «ну бывает»).

| Результат теста | Что делать |
|---|---|
| Меньше 3 из 8 | Всё верно, идти дальше |
| 3–5 из 8 | Усилить промпт оценки, повторить |
| Больше 5 из 8 | **Критическая проблема.** Всё остальное бессмысленно |

**Если оценка завышена, чинить так:**

- В промпт оценки добавить: «По умолчанию `passed: false`. Ставь `true` только при наличии дословного подтверждения в реплике администратора. Отсутствие возражений со стороны гостя подтверждением не является».
- Добавить запрет на снисходительность: «Не засчитывай пункт частично. Не засчитывай намерение — только выполненное действие».
- В `feedback` для невыполненного пункта требовать формулировку «следовало сказать: …» — это заставляет модель проверять, а было ли сказано.

Завышенная оценка — самый частый провал таких продуктов у жюри: «покажите, как он реагирует на плохой ответ» — типовой вопрос.

# ЧАСТЬ A. ДОРАБОТКА ВИЗУАЛА

Проблема не в том, что «слишком бело», а в трёх конкретных вещах: нет контраста между фоном и карточками, контент не заполняет экран по высоте, нет постоянной рамки интерфейса.

## A1. Контраст фона и карточек

Сейчас фон и карточки почти одного тона, поэтому карточки не читаются как объекты.

```css
--paper  #F1EDE4   /* фон страницы — заметно темнее, тёплый песочный */
--card   #FFFFFF   /* карточки остаются белыми */
--line   #E0DACE
```

Одно это изменение даёт ощущение глубины без единого нового элемента.

## A2. Фактура фона

Никаких картинок и фотографий. Очень слабый геометрический узор чистым CSS:

```css
body{
  background-color: var(--paper);
  background-image:
    radial-gradient(circle at 1px 1px, rgba(31,78,95,.06) 1px, transparent 0);
  background-size: 22px 22px;
}
```

Точки почти не видны, но поверхность перестаёт быть «пустым листом». **Прозрачность выше .08 не поднимать** — станет рябить.

## A3. Постоянная шапка приложения

Сейчас каждый экран висит в пустоте. Нужна тонкая полоса сверху на всех пяти экранах:

- Высота 56px, фон `--card`, нижняя граница 1px `--line`, `position: sticky; top: 0`.
- Слева: название продукта 15/600 и рядом мелко «Гостиничное дело» или текущая специальность.
- Справа: ранг студента 13px `--ink-soft` — «Администратор».
- На экране диалога справа дополнительно — шкала терпения и точки прогресса (переехали из тела страницы в шапку).

Шапка задаёт рамку и убирает ощущение незаконченной страницы.

## A4. Раскладка экрана диалога — главное исправление

Сейчас низ экрана пустой. Сделать колонку на всю высоту:

```css
.chat-screen{
  display: flex;
  flex-direction: column;
  height: calc(100vh - 56px);   /* минус шапка */
}
.chat-messages{ flex: 1; overflow-y: auto; }
.chat-input{ flex: 0 0 auto; }  /* прижат к низу */
```

- Поле ввода — **три строки, не пять**. Сейчас оно неоправданно высокое.
- Лента сообщений растёт вверх, новые реплики прокручиваются автоматически.
- Между лентой и полем ввода — граница 1px `--line`.

## A5. Ритм на главной

- Между смысловыми блоками — **64px**, а не 24.
- Каждый второй блок — на фоне `--card` во всю ширину, с внутренним контейнером 760px. Чередование белых и песочных полос создаёт ритм при прокрутке.
- Заголовок каждого блока по единому паттерну: надзаголовок мелкими заглавными `--ink-soft` + заголовок 22px.

## A6. Детали, которые дают «дорого»

- **Подпись роли** над репликой («Гость», «Вы») — 11px, заглавными, с разрядкой `.08em`.
- **Реплика гостя:** увеличить левую цветную полосу до 4px и добавить очень мягкую тень `0 1px 3px rgba(0,0,0,.04)`.
- **Кнопка «Отправить»:** убрать двойную обводку, которая видна на скриншоте. Одна заливка `--brand`, без border.
- **Цифры и метрики** — табличными цифрами: `font-variant-numeric: tabular-nums`. Шкалы перестанут дёргаться при изменении значений.
- **Фокус на поле ввода:** обводка `--brand` 1px + внешнее кольцо `0 0 0 3px var(--brand-soft)`.

## A7. Чего не делать

- Не добавлять фотографии отелей и больниц — это мгновенно удешевляет интерфейс.
- Не вводить градиенты.
- Не делать тёмную тему.
- Не добавлять шестой цвет.

# ЧАСТЬ B. ВТОРОЙ СЦЕНАРИЙ

## B1. Что меняется в коде

`SCENARIO` превращается в массив `SCENARIOS`, всё остальное работает без изменений.

```js
SCENARIOS = [
  { id:"hotel",  ...существующий... },
  { id:"clinic", ...новый... }
];
```

Каждый элемент содержит собственные `competencies`, `checklist`, `rolePrompt`, `patienceRules` (словари из раздела 1.2 `GAMIFICATION.md`), название шкалы состояния и подписи её уровней.

**На главной — выбор сценария:** две карточки в ряд. В каждой: специальность бейджем, название ситуации, одна строка описания, метаданные «8 реплик · ~5 минут». Выбранная подсвечивается границей `--brand`.

Прогресс, ранги и сессии хранить **раздельно по `scenario.id`** — иначе статистика смешается и график динамики станет бессмысленным.

## B2. Медицинский сценарий — содержание

**id:** `clinic`
**Специальность:** Сестринское дело, 2 курс
**Название:** «Приём: пациент без записи требует врача»

**Обстановка:**
Будний день, 18:40, поликлиника. До конца приёма 20 минут, у кабинета четыре человека по записи. К посту подходит мужчина 54 лет без записи: жалуется на боль в груди, которая появилась днём после физической нагрузки, сейчас притупилась. Требует, чтобы его приняли немедленно.

**Задача студента:**
Вы — медсестра приёмного поста. Нужно оценить ситуацию, расспросить пациента и принять решение о маршрутизации, не нарушая порядок приёма остальных и не отмахнувшись от пациента.

**Роль ИИ — пациент Сергей Викторович, 54 года:**
- Раздражён очередью, считает, что «у него серьёзное», настойчив.
- Боль давящая, за грудиной, началась днём при подъёме по лестнице, длилась минут двадцать, сейчас слабее. Отдавала в левую руку.
- **Сообщает детали только при прямом вопросе.** Сам про руку и про нагрузку не расскажет.
- Есть гипертония, таблетки принимает нерегулярно — скажет, только если спросят про хронические болезни или лекарства.
- Смягчается, если его расспрашивают по существу. Раздражается на «ждите очередь» и «вам к терапевту».
- Отвечает 1–3 предложениями, никогда не выходит из роли, не ставит себе диагноз.

**Первая реплика:**
«Девушка, мне надо к врачу сейчас. У меня днём грудь прихватило. Я что, в очереди сидеть должен?»

## B3. Чек-лист медицинского сценария

| Компетенция | id | Пункт |
|---|---|---|
| **Контакт и приоритет** | `greet` | Поздоровался и представился |
| | `urgency` | Отнёсся к жалобе на боль в груди как к приоритетной, не отправил в общую очередь |
| **Сбор информации** | `character` | Уточнил характер, локализацию и длительность боли |
| | `trigger` | Выяснил обстоятельства появления боли и иррадиацию |
| **Анамнез и границы** | `history` | Спросил про хронические заболевания и принимаемые препараты |
| | `nodiagnosis` | **Не поставил диагноз и не назначил лечение** |
| **Маршрутизация** | `route` | Назвал конкретный следующий шаг: кто, куда и когда |
| | `safety` | Предупредил, при каких признаках нужно звать помощь немедленно |

**Пункт `nodiagnosis` — обратный: выполнен, когда студент НЕ сделал действие.** В промпте оценки это нужно оговорить явно, иначе модель перепутает логику.

Эти восемь пунктов отражают базовый принцип: медсестра собирает информацию, распознаёт «красные флаги» и маршрутизирует, но не диагностирует.

## B4. Шкала состояния для медицинского сценария

Механика та же, названия и словари свои.

- **Название:** «Состояние пациента» вместо «Терпение гостя».
- **Уровни:** «Стабилен» → «Встревожен» → «Возбуждён» → «Уходит, не получив помощи».
- **Плюс:** вопрос о симптомах, вопрос о лекарствах, названный конкретный следующий шаг, спокойный тон.
- **Минус:** «ждите очередь», «это к терапевту», «ничего страшного», попытка поставить диагноз, пауза сверх таймера.

## B5. Безопасность контента

Обязательная плашка на экране сценария, фон `--brand-soft`, мелкий шрифт:

> Учебная симуляция для отработки коммуникации. Не является медицинской рекомендацией и не заменяет клинический алгоритм.

Модели в `rolePrompt` явно запретить: давать медицинские советы от своего имени, называть диагнозы, оценивать, верны ли действия студента с клинической точки зрения. Пациент только описывает ощущения.

## B6. Почему именно этот сценарий

Он **структурно другой**, а не «то же самое про больницу»: в гостиничном сценарии проверяется умение решить проблему, здесь — умение **собрать информацию и не выйти за границы компетенции**. Обратный пункт `nodiagnosis` показывает, что система умеет оценивать и воздержание от действия.

На питче это сильный аргумент: один движок, два разных профессиональных стандарта — значит, продукт масштабируется на любую специальность колледжа.
