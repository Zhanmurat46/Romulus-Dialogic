# DESIGN_UPGRADE.md

**Дополнение к `MVP_MASTER_PLAN.md`.** Раздел 2 основного плана задаёт визуальный язык (цвета, шрифты, отступы). Этот файл задаёт **содержание экранов** — то, чего в плане не хватало и из-за чего интерфейс вышел пустым.

При конфликте приоритет у этого файла.

---

# 1. ПРИНЦИП

Красиво ≠ разноцветно. Продукт выглядит дорого за счёт **плотности полезного содержания, воздуха и одного акцента**, а не за счёт количества цветов.

**Правило одного акцента:** на экране одна вещь притягивает взгляд первой. На главной — кнопка «Начать». На результате — блок цитаты. Всё остальное тише.

---

# 2. РАСШИРЕНИЕ ПАЛИТРЫ

К палитре из раздела 2.2 добавляются только служебные оттенки для графики:

```css
--accent-1  #1F4E5F   /* петролевый — основной, уже есть */
--accent-2  #C97B3F   /* терракота — второй акцент в графике */
--accent-3  #6B8F71   /* приглушённый зелёный */
--accent-4  #8C7A9B   /* пыльный лиловый */
--track     #EDEAE3   /* «пустая» часть шкал и колец */
```

Четыре акцента — **потолок**. Они тёплые и приглушённые, поэтому не превращают продукт в детский дашборд.

# 3. ЭКРАН 1 — ГЛАВНАЯ

Сейчас там две кнопки. Должно быть пять блоков.

### 3.1 Шапка-герой

- **Надзаголовок** мелким шрифтом, цвет `--ink-soft`, разрядка: `СИМУЛЯТОР ПРОФЕССИОНАЛЬНОЙ ПРАКТИКИ`
- **Заголовок** 38px/1.15, максимум две строки: «Отработайте сложную ситуацию до того, как встретите её на практике»
- **Подзаголовок** 17px, `--ink-soft`, максимум 2 строки: «Вы ведёте диалог с клиентом. Потом получаете разбор по профессиональному чек-листу — с цитатами из ваших же реплик.»
- **Кнопки:** «Начать симуляцию» (основная) и «Посмотреть пример разбора» (вторичная, ведёт в Demo-режим)
- Под кнопками мелкая подпись: «Занимает 5–7 минут. Регистрация не нужна.»

### 3.2 Блок «Как это работает» — три шага

Три карточки в ряд, на узком экране — в столбик.

| № | Заголовок | Описание |
|---|---|---|
| 01 | Получаете ситуацию | Реальный случай с практики и чек-лист, по которому вас оценят |
| 02 | Ведёте диалог | Клиент реагирует на то, что вы говорите, а не по сценарию |
| 03 | Видите разбор | Каждый вывод подкреплён дословной цитатой из вашей реплики |

**Оформление:** номер крупно (32px, `--track`, за текстом или сверху), заголовок 16/600, описание 14px `--ink-soft`. Иконок нет — номера выразительнее и не выглядят как сток.

### 3.3 Блок «Чем отличается от обычного чата»

Две колонки, сравнение. Это главный аргумент продукта, и он должен быть на виду, а не только в питче.

| Обычный ИИ-чат | Этот симулятор |
|---|---|
| Отвечает на вопросы | Играет клиента, который реагирует на ваше поведение |
| Даёт общий отзыв в свободной форме | Оценивает по профессиональному чек-листу |
| «В целом неплохо, будьте вежливее» | «Пункт «извинился» не выполнен — вот ваша реплика» |

Левая колонка на фоне `--track`, правая на `--brand-soft` с левой границей `--brand`. Контраст фонов делает мысль очевидной без пояснений.

### 3.4 Блок «Для кого»

Одна строка текста, без карточек: «Студенты колледжей по специальностям сферы обслуживания — гостиничное дело, сервис, продажи. Преподаватель получает расшифровку и заполненный чек-лист.»

### 3.5 Подвал

Одна строка: название команды, VentureHack 2026, Трек 2 — EduTech. Мелко, `--ink-soft`.

- **Плашка специальности** сверху: маленький бейдж с фоном `--brand-soft` — «Гостиничное дело · 2 курс».

- **Строка метаданных** перед кнопкой: «8 реплик · около 5 минут · оценка по 8 критериям».

# 5. ЭКРАН 4 — АНАЛИЗ

Сейчас по плану пункты проступают по очереди. Усилить:

- Заголовок: «Сверяю ваши реплики с чек-листом».
- Пункты проступают **группами по компетенциям**, с шагом 500ms: сначала название компетенции, затем её пункты.
- Рядом с каждым проступившим пунктом — тонкая полоска `--track`, заполняющаяся `--brand` за 300ms. Создаёт ощущение работы, а не ожидания.
- Внизу мелко: «Обычно занимает 5–10 секунд».

# 6. КОМПЕТЕНЦИИ — ОСНОВА ДЛЯ ГРАФИКИ

Восемь булевых значений — слишком мало для осмысленной инфографики. Решение: **группировка в 4 компетенции**. Это даёт данные для визуализации и превращает список галочек в профиль навыков.

```js
COMPETENCIES = [
  { id:"contact",   name:"Установление контакта", color:"--accent-1", items:["greet","apology"] },
  { id:"diagnosis", name:"Выяснение ситуации",    color:"--accent-2", items:["details","noblame"] },
  { id:"solution",  name:"Поиск решения",         color:"--accent-3", items:["option","choice"] },
  { id:"closing",   name:"Завершение",            color:"--accent-4", items:["compens","close"] }
];
```

Это добавление к `SCENARIO`, сами пункты чек-листа не меняются.

**Педагогический смысл:** «вы проседаете в завершении разговора» полезнее, чем «6 из 8».

# 7. ЭКРАН 5 — РЕЗУЛЬТАТ

Главный экран. Порядок блоков сверху вниз.

### 7.1 Кольцевая диаграмма

- **Чистый inline SVG, без библиотек.** Кольцо строится через `stroke-dasharray` на `<circle>`. Chart.js и прочее не подключать: лишняя зависимость ради одного кольца.
- Диаметр 140px, толщина 14px, фон кольца `--track`.
- **Четыре дуги по компетенциям**, каждая своим цветом, длина дуги пропорциональна выполненным пунктам внутри компетенции.
- В центре кольца крупно «6/8», под ним мелко «75%».
- Анимация: `stroke-dashoffset` с `transition` 800ms `ease-out` при появлении экрана.
- Справа от кольца — легенда: цветная точка, название компетенции, «2/2».

### 7.2 Профиль компетенций — горизонтальные полосы

Четыре строки. В каждой: название слева, полоса справа, значение в конце.

- Высота полосы 10px, радиус 5px, фон `--track`, заливка — цветом компетенции.
- Анимация ширины 600ms с задержкой 80ms между строками.
- **Самая слабая компетенция подсвечена:** её название полужирным, справа мелкая подпись «зона роста».

Это и есть «инфографика», которую вы хотели, — но она несёт смысл, а не украшает.

### 7.3 Главный вывод одной строкой

Крупная плашка на `--brand-soft`: «Сильнее всего — установление контакта. Слабее всего — завершение разговора.»

Генерируется кодом из подсчёта, не моделью. Надёжнее и бесплатно.

### 7.4 Разбор по пунктам

Как в разделе 2.6 основного плана, но **сгруппированный по компетенциям**, с заголовком группы. Невыполненные пункты — первыми внутри каждой группы.

### 7.5 Динамика по попыткам

Появляется **только со второй попытки** — данные берутся из localStorage.

- Простой линейный график на inline SVG: ось X — номер попытки, ось Y — результат из 8.
- Точки соединены линией `--brand`, текущая попытка — увеличенная точка.
- Подпись: «Ваш прогресс: попытка 1 — 4/8, попытка 2 — 6/8».

**Зачем:** это сильнейший аргумент на питче. Обучение доказывается ростом, а рост виден на графике. Ради этого стоит попросить двух студентов пройти симулятор дважды.

### 7.6 Действия

Кнопки: «Пройти заново», «Скачать CSV». Расшифровка — в свёрнутом `<details>`.

# 8. ОБЩИЕ ПРАВИЛА ОФОРМЛЕНИЯ

- **Воздух важнее украшений.** Между смысловыми блоками главной — 56px, а не 16.
- **Максимум ширины текста — 680px** даже внутри контейнера 760px. Длинные строки читаются плохо.
- **Заголовки секций** на главной: надзаголовок мелкими заглавными `--ink-soft` + заголовок 22px. Единый паттерн на всех блоках.
- **Ни одной иконки-картинки.** Номера, цветные точки, полосы, кольцо — этого достаточно и выглядит цельно.
- **Никаких теней глубже** `0 1px 3px rgba(0,0,0,.05)`.
- **Скругления только двух радиусов:** 10px у кнопок и полей, 14px у карточек.
