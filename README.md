# Dialogic

Симулятор профессиональной практики для студентов колледжей: студент ведёт трудный разговор с клиентом или пациентом, а затем получает разбор по профессиональному чек-листу, где каждый вывод подкреплён дословной цитатой из его собственных реплик.

**Живое демо:** https://dialogic-app.vercel.app
Кнопка «Посмотреть пример разбора» показывает готовый разбор без сети и без обращения к модели.

> До 26.09.2026 продукт назывался Praxis. Старый адрес https://07-praxis.vercel.app продолжает работать и ведёт на ту же версию. Старое имя осталось также во внутренних ключах хранилища: их переименование стёрло бы сохранённые прогоны студентов.

## Проблема и пользователь

**Проблема.** Мест производственной практики мало. Отработать трудный разговор с раздражённым гостем или встревоженным пациентом студенту негде, кроме реальной работы. Ролевые игры на занятиях не масштабируются: преподаватель не может присутствовать на каждом отыгрыше и разбирать каждую реплику.

**Пользователи:**

- **Студент колледжа**: гостиничное дело, сестринское дело, сервис и продажи. Он проходит ситуацию до практики, видит, какие пункты профстандарта не выполнил, и повторяет попытку.
- **Преподаватель.** Он получает расшифровку диалога и заполненный чек-лист с цитатами (экспорт в CSV) и не присутствует при каждом прогоне.

**Чем это отличается от обычного ИИ-чата.** Чат может сыграть клиента, но оценит «в целом неплохо, будьте вежливее». Dialogic оценивает по конкретным пунктам и показывает реплику, в которой пункт выполнен или нарушен. Диалог здесь только способ получить материал для оценки, ценность продукта в разборе.

### Что есть в MVP

- Три сценария трёх специальностей: «Заселение: бронь не найдена» (гостиничное дело), «Приём: пациент без записи требует врача» (сестринское дело) и «Возврат: товар без чека» (торговое дело). Движок один, сценарии описываются данными: третий сценарий добавлен без единой правки логики.
- Чек-лист из 8 пунктов виден студенту **до** начала диалога. Пункты сгруппированы в 4 компетенции.
- Шкала состояния собеседника (терпение гостя или состояние пациента). Её считает код по правилам сценария, модель в этом не участвует. При нуле собеседник уходит, и это решение кода: модели запрещено самой объявлять уход.
- «Обратные» пункты: засчитываются, если студент чего-то **не** сделал. Например, «не обвинил гостя, систему или коллег» или «не поставил диагноз».
- Лимит в 8 реплик и необязательный таймер 45 секунд на реплику.
- Режим «Сложный собеседник»: собеседник резче, перебивает, требует руководителя и сообщает скрытые данные только со второго прямого вопроса. Шкала стартует ниже (55 вместо 70), а отрицательные правила бьют в 1,5 раза сильнее. Чек-лист и оценка те же, поэтому результаты двух режимов сравнимы.
- Видимые последствия: когда состояние собеседника опускается на уровень, в ленте появляется строка последствия («гость требует позвать старшего администратора»). На экране результата есть строка «Чем закончилось для дела».
- Экран результата: счёт из 8, профиль компетенций, значки, ранг, разбор по пунктам (невыполненные первыми), график динамики по попыткам, расшифровка, экспорт CSV.
- Demo-режим без сети. Он рисуется тем же кодом, что и живой результат.
- Голос, необязательно и выключено по умолчанию: озвучка реплик собеседника и голосовой ввод. Распознанный текст только дописывается в поле, отправляет всегда человек. Если браузер не поддерживает голос, кнопок нет. При отказе в доступе к микрофону кнопка исчезает, а под полем появляется строка «Голосовой ввод недоступен — печатайте». Клавиатура работает в любом случае.
- Кнопка «Скопировать разбор для преподавателя» кладёт в буфер обмена обычный текст: сценарий, дату, счёт, каждый пункт с цитатой и комментарием, расшифровку. Его можно сразу вставить в мессенджер или почту.

### Доступность

- Весь путь от выбора сценария до разбора проходится только с клавиатуры: Tab, Enter, пробел и Ctrl+Enter для отправки реплики. При смене экрана фокус переходит на его заголовок. Путь проверен автоматически: на каждом шаге фокус на ожидаемом элементе, у интерактивных элементов видна рамка фокуса.
- Первый элемент страницы — ссылка «К основному содержанию», видимая при фокусе.
- Лента диалога размечена как `role="log"` с `aria-live="polite"`, чтобы экранный диктор объявлял новые реплики собеседника. Значки размечены с названием и статусом, декоративные SVG скрыты от дикторов (`aria-hidden`). С реальным экранным диктором не проверялось.
- Контраст любого текста мельче 16px не ниже 4.5:1. Проверено автоматическим обходом всех экранов на ширине 360, 390 и 1280 px.
- `prefers-reduced-motion` отключает анимации.
- Вёрстка на ширине телефона (360 и 390 px) проверена в эмуляции Chrome: без горизонтальной прокрутки, страница диалога не прокручивается целиком.
- Экранная клавиатура: в `viewport` указан `interactive-widget=resizes-content`, для Safari на iPhone высота экрана диалога подгоняется по `visualViewport`. На реальных устройствах это не подтверждено.
- Голос (озвучка реплик и голосовой ввод) реализован через Web Speech API браузера и проверен в Chrome. В браузерах без поддержки кнопки голоса не показываются, клавиатурный ввод работает всегда.

## Запуск локально

Нужны Node.js 18 или новее и ключ Gemini API. Ключ бесплатный, его выдаёт https://aistudio.google.com в разделе Get API key.

```bash
npm i -g vercel        # один раз: CLI Vercel
vercel login           # один раз: вход в аккаунт Vercel
vercel link            # один раз: привязать папку к проекту на Vercel
```

Создайте в корне проекта файл `.env`. Он уже в `.gitignore` и в репозиторий не попадёт:

```
GEMINI_API_KEY=ваш_ключ
```

Запустите:

```bash
vercel dev             # статика и функция api/ на http://localhost:3000
```

Открывать `index.html` двойным кликом нельзя: страница откроется, но функция `api/gemini.js` запускается только через `vercel dev` или на Vercel.

### Без аккаунта Vercel: только интерфейс и demo

Если не хотите заводить аккаунт, поднимите статику любым статическим сервером, например:

```bash
npx serve .            # откроется на http://localhost:3000
```

Так работают весь интерфейс и demo-режим («Посмотреть пример разбора» во всех трёх сценариях). **Живой диалог так не работает**: ему нужна серверная функция `api/gemini.js`, а статический сервер её не выполняет, и запрос к модели вернёт ошибку. Живой диалог доступен только через `vercel dev` (см. выше) или на опубликованной версии.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `GEMINI_API_KEY` | да | Ключ Google Gemini. Хранится **только** в переменных окружения: на Vercel или в локальном `.env`. В коде и в git его нет |
| `ACCESS_CODE` | нет | Если задана, функция принимает только запросы с заголовком `x-access-code`, равным этому значению. Значение должно совпадать с константой `ACCESS_CODE` в `index.html`. Локально её можно не задавать: тогда проверка отключена |
| `GEMINI_MODELS` | нет | Позволяет заменить список моделей без правки кода, через запятую: `model-a,model-b` |

Для продакшена переменные добавляются так:

```bash
vercel env add GEMINI_API_KEY production
vercel env add ACCESS_CODE production
vercel --prod
```

```
├── api/
│   └── gemini.js    serverless-функция Vercel: прокси к Gemini, ключ на сервере
├── fonts/           шрифты Literata и Inter (woff2) и их лицензии OFL
├── .vercelignore    на сайт публикуются только index.html, api/ и fonts/
├── .gitignore
├── LICENSE          MIT для кода; шрифты — под своей лицензией OFL 1.1
├── README.md
└── CLAUDE.md, MVP_MASTER_PLAN.md, DESIGN_UPGRADE.md, GAMIFICATION.md, PHASE_3_5.md
                     — рабочие планы по этапам разработки
```

Пользовательский путь состоит из пяти экранов: **Главная → Сценарий → Диалог → Анализ → Результат**. Экраны переключает одна функция `show()`.

### `index.html`

- **Сценарии как данные.** Массив `SCENARIOS`: ситуация, задача, чек-лист с критериями для оценщика, группы компетенций, промпт роли, правила шкалы состояния, тексты исходов. Новая специальность добавляется новым объектом, логика не меняется.
- **Шкала состояния** считается кодом (`patienceDelta()`). Сдвиг за реплику складывается из общей механики (скорость ответа, слишком короткая реплика, пауза по таймеру) и ключевых слов сценария: извинение, уточняющий вопрос и конкретика повышают шкалу, отговорки понижают. Когда шкала опускается до 25% и ниже, к промпту роли добавляется указание отвечать резче.
- **Хранение.** Прогоны лежат в `localStorage`, отдельно по сценариям (ключи `praxis.sessions.<id>`), до 50 последних. На их основе строятся ранги, значки, график динамики и CSV.
- **Экспорт CSV:** разделитель `;` и BOM, чтобы кириллица без искажений открывалась в Excel с русской локалью. В конце файла есть сводка: процент выполнения каждого пункта и пункт, который проваливают чаще всего.

### `api/gemini.js`

- Принимает `POST` с полями `contents`, `system` и `generationConfig` и передаёт их в Gemini `generateContent`.
- **Ключ только на сервере.** Жюри и студенты открывают ссылку, ключ им не нужен и в браузере не виден.
- **Перебор моделей.** Модели пробуются по очереди, пока одна не ответит: `gemini-3.6-flash` → `gemini-3.5-flash-lite` → `gemini-flash-latest` → `gemini-flash-lite-latest`. На бесплатном тарифе у части моделей суточная квота нулевая, и `429` или `404` приходит на первый же запрос. Перебор снимает эту проблему без участия пользователя.
- Таймаут 40 секунд на модель. Если не ответила ни одна, возвращается текст ошибки Google от последней попытки и список всех попыток. Ошибка не подменяется общей фразой, чтобы её можно было диагностировать.

### Почему без сборки и фреймворков

| Решение | Причина |
|---|---|
| Один статический `index.html` | Ноль сборки и конфигурации: Vercel сам отдаёт статику и находит папку `api/`. Меньше точек отказа перед демо |
| Без React, Vue и `package.json` | Интерфейс состоит из пяти экранов, и фреймворк добавил бы часы настройки без выигрыша для пользователя |
| Без `type="module"` | ES-модули ломаются при открытии страницы через `file://` |
| Одна serverless-функция | Единственная задача сервера — спрятать ключ и перебрать модели |
| Без базы данных и авторизации | Сессия однопользовательская, `localStorage` хватает. Регистрация не нужна, и это снижает порог входа для студента |

## Как устроена оценка

К модели идут два типа запроса через одну и ту же функцию `api/gemini.js`. Они различаются системной инструкцией и `temperature`. Отдельных констант или параметров режима в коде нет: тип запроса задаётся тем, что `index.html` кладёт в тело запроса.

| Тип запроса | Системная инструкция | Что делает модель | temperature |
|---|---|---|---|
| Роль собеседника | промпт роли из сценария (`rolePrompt`) | Играет собеседника и получает всю историю диалога | 0.9 |
| Оценка | инструкция методиста с чек-листом (`assessPrompt()`) | Получает расшифровку, возвращает JSON-оценку | 0.2 |

Запросы разделены намеренно: модель, которая только что играла роль, оценивает диалог необъективно. Оценщик не видит промпт роли. Он получает отдельную системную инструкцию методиста: оценивать только реплики студента, быть строгим («сомневаешься — false»), правильно обращаться с обратными пунктами.

### Три уровня разбора ответа

1. **`responseSchema`.** Запрос с `responseMimeType: "application/json"` и схемой: `items[]` с полями `id`, `quote`, `passed`, `feedback` и отдельное поле `summary`.
2. **Повтор без схемы.** Если ответ по схеме не удался, запрос повторяется с текстовым требованием вернуть только чистый JSON.
3. **Терпеливый парсер.** Срезает обёртку ```` ```json ````. Если разобрать всё равно не удалось, берёт подстроку от первой `{` до последней `}`.

После этого `normalize()` достраивает пункты, которые модель пропустила, из чек-листа сценария. Разбор всегда состоит ровно из 8 пунктов в правильном порядке.

### Проверка цитат: `quoteFound()` и флаг `fabricated`

Главный вопрос к любой ИИ-оценке: а вдруг модель выдумывает. Поэтому каждая цитата проверяется кодом:

- Оценщику предписано приводить **дословный непрерывный фрагмент одной реплики студента**, без перефразирования, склеек и многоточий.
- `quoteFound()` ищет цитату в репликах студента. При сравнении игнорируются регистр, различие «ё» и «е», пунктуация и лишние пробелы. Но слова должны идти подряд и **внутри одной реплики**: склеить куски разных реплик или процитировать собеседника нельзя.
- Если цитата не найдена, пункт получает флаг `fabricated`, и на экране результата рядом с ней появляется бейдж **«цитата не подтверждена»**.

Модель не может похвалить студента за то, чего не было в тексте, и это видно и студенту, и преподавателю.

Итоговый вывод («сильнее всего…, слабее всего…»), ранг и значки считает код по результатам пунктов, а не модель.

## Как проверялся продукт

Проверка перед сдачей шла на опубликованной версии https://dialogic-app.vercel.app с живой моделью. Браузером управлял скрипт: Chrome без окна через DevTools Protocol. **Реплики студента для прогонов написала команда.** Это проверка того, что движок работает правильно, а не исследование на студентах.

### 12 живых прогонов

Каждый из трёх сценариев прошёл в обоих режимах (обычный и «Сложный собеседник»), и в каждом случае — один намеренно плохой и один хороший диалог.

| | Плохой диалог | Хороший диалог |
|---|---|---|
| Реплики студента | 3 короткие реплики с нарушениями, например «Такое бывает, система глючит.», «Это у вас, наверное, остеохондроз, выпейте таблетку.», «Таковы правила, ничего не могу сделать.» | 4–8 реплик, в которых выполнены пункты чек-листа |
| Результат | **0 из 8** во всех 6 прогонах | **8 из 8** во всех 6 прогонах |
| Обратный пункт (`noblame`, `nodiagnosis`, `norules`) | Не выполнен во всех 6 прогонах, цитата — реплика с нарушением | Выполнен во всех 6 прогонах |
| Цитаты, не найденные в расшифровке | 0 | 0 |

Во всех 12 прогонах (96 оценённых пунктов) нет ни одной цитаты, которую не подтвердила бы сверка `quoteFound()`, ни одной ошибки ответа модели и ни одной ошибки JavaScript.

Хорошие реплики писались под критерии чек-листа, поэтому результат 8 из 8 для них ожидаем. Прогоны показывают, что оценка уверенно различает явно плохой и явно хороший диалог. Точность на пограничных случаях они не измеряют: для этого нужно сравнение с оценкой преподавателя (см. «Ограничения MVP»).

### Дополнительные автоматические проверки

На той же версии кода, запущенной локально.

- **Путь только с клавиатуры** от главной до кнопки «Скопировать разбор»: фокус не теряется, рамка фокуса видна.
- **Контраст** любого текста мельче 16px не ниже 4.5:1 на всех экранах, на ширине 360, 390 и 1280 px.
- **Экран диалога** не прокручивается целиком на ширине от 360 до 1280 px. Шапка диалога помещается без наложений.
- **Голос в Chrome.** Логика проверена с подменой Web Speech API:
  - озвучка выключена по умолчанию;
  - речь обрывается при отправке реплики, при «Завершить» и при уходе с экрана;
  - распознанный текст дописывается в поле и не отправляется сам;
  - при отказе в доступе к микрофону кнопка исчезает, а Ctrl+Enter продолжает отправлять.

  В обычном Chrome API распознавания речи и русские голоса есть, и кнопки голоса появляются.
- **Хранение прогонов** раздельное по сценариям: `praxis.sessions.hotel`, `praxis.sessions.clinic`, `praxis.sessions.retail`.

## Ограничения MVP

- **Оценка опирается на суждение одной модели.** Цитаты проверяются кодом, но решение «выполнен или нет» принимает модель. Слепого сравнения с оценкой преподавателя пока не проводилось.
- **Нет кабинета преподавателя.** Результаты хранятся в браузере студента (`localStorage`) и передаются преподавателю через CSV.
- **Только русский язык.** Три сценария и три специальности.
- **Бесплатный тариф Gemini.** При исчерпании квоты всех моделей из списка живой диалог недоступен, на этот случай есть demo-режим.
- **`ACCESS_CODE` защищает только от случайных ботов.** Код лежит в клиентском коде и виден в открытом репозитории. Это осознанный компромисс для хакатона: после него код нужно сменить одновременно в `index.html` и на Vercel.
- **Шкала состояния работает на ключевых словах.** Это прозрачно и предсказуемо, но формулировку без ключевых слов шкала может не заметить.

## Дорожная карта

- Кабинет преподавателя: учётная запись и база данных, группы, сводка по пунктам, которые проваливают чаще всего.
- Проверка качества оценки: слепое сравнение вердиктов модели с оценкой преподавателей на реальных прогонах.
- Редактор сценариев для методистов: чек-лист и роль собеседника задаются без программирования.
- Новые специальности по профстандартам колледжей.
