## 2. Что это за продукт

**Dialogic** (до 26.09.2026 назывался Praxis) — симулятор профессиональной практики для студентов колледжей.

- **Проблема:** мест производственной практики мало, отрабатывать трудные разговоры с клиентами и пациентами студенту негде. Преподаватель физически не может присутствовать на каждом отыгрыше роли.
- **Пользователь:** студент колледжа (гостиничное дело, сестринское дело, продажи и сервис). Второй пользователь — преподаватель, он получает расшифровку и заполненный чек-лист.
- **Ценность:** не в самом диалоге, а в **разборе по профессиональному чек-листу, где каждый вывод подкреплён дословной цитатой из реплик самого студента.** Диалог — лишь способ добыть материал для оценки.
- **Отличие от ChatGPT:** обычный чат поговорит в роли клиента, но не скажет, какой пункт профстандарта нарушен и в какой именно реплике.

**Контекст:** финал хакатона VentureHack 2026, направление EduTech. Оценивают: проблема и исследование 20, инновационность 20, техническая реализация 25, UX и доступность 15, потенциал развития 10, презентация 10.

## 3. Пользовательский путь — пять экранов, больше не добавлять

```
[1] Главная → [2] Сценарий → [3] Диалог → [4] Анализ → [5] Результат
                                  ↑                          │
                                  └──── «Пройти заново» ──────┘
```

1. **Главная** — выбор сценария карточками, «Начать симуляцию», «Посмотреть пример разбора» (demo-режим).
2. **Сценарий** — ситуация, задача, чек-лист показан ЗАРАНЕЕ, ресурсы студента.
3. **Диалог** — реплики, шкала терпения собеседника, точки прогресса, таймер, лимит 8 реплик.
4. **Анализ** — отдельный экран 5–10 с, пункты чек-листа проступают по очереди. Это не спиннер, а витрина работы продукта.
5. **Результат** — счёт из 8, кольцо, профиль компетенций, значки, разбор по пунктам с цитатами, график динамики, расшифровка, CSV.

## 4. Архитектура

```
/
├── index.html       ← весь фронтенд: HTML + CSS + JS в одном файле
├── api/gemini.js    ← serverless Vercel, держит GEMINI_API_KEY
├── fonts/           ← самохостинг шрифтов (добавляется по плану)
├── .gitignore
├── CLAUDE.md
├── DIALOGIC_FINAL_PLAN.md
└── MVP_MASTER_PLAN.md
```

**Принципиально:** без фреймворков, без сборки, без `package.json`, без базы данных, без `type="module"`. Vercel сам определяет статику и папку `api/`.

**Два режима запроса к модели, одна функция:**

| Режим | Назначение | temperature |
|---|---|---|
| `roleplay` | модель играет собеседника, получает всю историю | 0.9 |
| `assess` | модель получает расшифровку и чек-лист, возвращает JSON | 0.2 |

Разделены намеренно: модель, только что игравшая роль, оценивает себя необъективно.

**Надёжность оценки — три уровня парсинга:** `responseSchema` → повтор без схемы с требованием чистого JSON → срез обёртки ```` ```json ```` и подстрока от первой `{` до последней `}`. Затем `normalize()` достраивает недостающие пункты.

**Перебор моделей обязателен** — на бесплатном тарифе у части моделей суточная квота нулевая, 429 приходит на первый же запрос.

## 5. Инварианты — ломать нельзя ни при каких правках

1. **`quoteFound()` и флаг `fabricated`.** Цитата ищется в ОДНОЙ реплике студента; не нашлась — бейдж «цитата не подтверждена». Это главный технический аргумент продукта, он отвечает на вопрос жюри «а вдруг ИИ выдумывает».
2. **Ключи `localStorage`: `praxis.sessions.hotel`, `praxis.sessions.clinic`, `praxis.sessions.retail`, `praxis.scenario`.** Переименование сотрёт накопленные прогоны студентов — это данные валидации. **Имена ключей не трогать никогда**, несмотря на переименование продукта.
3. **Ключ API только в переменных окружения Vercel.** Ни в `index.html`, ни в git.
4. **Собеседник может грозить уйти, но не может объявить уход.** Уход — решение кода при терпении 0.
5. **Невыполненные пункты на экране результата выводятся первыми.** Студент должен видеть зоны роста.
6. **Цитата — визуальный центр экрана результата**, заметнее комментария оценщика.
7. **Высота экрана диалога** `calc(100dvh - 56px)`: лента прокручивается внутри, страница целиком — нет.
8. **Demo-режим рисуется тем же кодом**, что и живой результат.
9. **`prefers-reduced-motion`** гасит анимации.
10. **Чек-лист виден студенту до начала диалога.**

## 7. Как работать

- Одна задача за раз. Закончил — остановился, написал, что проверить, ждёшь подтверждения. Следующую задачу сам не начинаешь.
- Команды терминала выписывать **отдельным списком**: пользователь выполняет их вручную и не является сильным разработчиком.
- Не рефакторить попутно. Не переименовывать классы, которые используются в JS.
- При поломке — минимальная правка, остальной код не трогать.
- Дизайн задан цифрами в финальном плане: цвета и отступы не обсуждать, брать оттуда.
