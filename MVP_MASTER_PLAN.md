# 1. ПРОДУКТ

## 1.1 Ценность

Студент проходит рабочую ситуацию в диалоге с ИИ-клиентом и получает **разбор по профессиональному чек-листу, где каждый вывод подкреплён дословной цитатой из его собственных реплик**.

Ценность не в диалоге, а в оценке с доказательствами. Диалог — способ добыть материал для оценки.

**Формула для питча:** «ChatGPT поговорит в роли клиента. Он не скажет, что именно вы нарушили по профессиональному стандарту, и не покажет, в какой реплике».

## 1.2 Пользователь

- **Основной:** студент колледжа (гостиничное дело, сервис, продажи) — мест практики мало, сложные ситуации отрабатывать негде.
- **Второй:** преподаватель — получает расшифровку и заполненный чек-лист вместо присутствия на каждом отыгрыше.

## 1.3 User flow

```
[1] Старт → [2] Сценарий → [3] Диалог → [4] Анализ → [5] Результат
                                ↑                          │
                                └──── «Пройти заново» ──────┘
```

**Пять экранов. Больше не добавлять.**

| Экран | Содержимое |
|---|---|
| **1. Старт** | Название, одна строка о сути, кнопки «Начать» и «Demo-режим». **Поля API-ключа нет** — ключ живёт на сервере |
| **2. Сценарий** | Карточка ситуации + чек-лист показан заранее + кнопка «Начать диалог» |
| **3. Диалог** | Реплики, точки-прогресс, индикатор «печатает», кнопки «Отправить» и «Завершить» |
| **4. Анализ** | Отдельный экран 5–10 сек: пункты чек-листа проступают по очереди. **Не спиннер** |
| **5. Результат** | «6 из 8» + шкала, карточки пунктов с цитатами, расшифровка в `<details>`, экспорт CSV |

Экран «Анализ» — единственный момент, где видно, что продукт делает работу преподавателя. Спрятать за спиннером = потерять главный эффект демо.

## 1.4 Сценарий для демо

**«Заселение: бронь не найдена».** Понятен жюри без пояснений, даёт конфликт, имеет проверяемый чек-лист.

- **Роль ИИ:** гость Андрей Соколов, 41 год, после шестичасового перелёта, раздражён, но не агрессивен.
- **Динамика:** смягчается на конкретику, злится на общие отговорки («такое бывает», «система глючит»), резко реагирует на обвинение.
- **Скрытые данные:** фамилия Соколов, бронь HTL-48120, две ночи — сообщает **только если спросят**. Так проверяется пункт «уточнил данные».
- **Первая реплика:** «Добрый вечер. У меня бронь, вот подтверждение. Только что мне сказали, что её нет в системе. Это как понимать?»
- **Лимит:** 8 реплик студента.

**Чек-лист (8 пунктов, каждый проверяем по тексту):**

| id | Пункт |
|---|---|
| `greet` | Поздоровался и представился |
| `apology` | Извинился до начала разбирательства |
| `details` | Уточнил данные брони |
| `noblame` | Не обвинил гостя, систему или коллег |
| `option` | Предложил конкретную альтернативу с деталями |
| `choice` | Дал выбор, а не поставил перед фактом |
| `compens` | Предложил компенсацию |
| `close` | Корректно завершил и подтвердил следующий шаг |

**Правило формулировки:** пункт должен быть наблюдаем в тексте. «Представился» — да. «Был вежлив» — нет.

## 1.5 Что судья видит за 2 минуты

| Время | Что | Критерий |
|---|---|---|
| 0:00–0:15 | Экран сценария: ситуация с реальной практики | Problem & Impact |
| 0:15–0:50 | Две реплики вживую: плохая и хорошая | Technical Execution |
| 0:50–1:05 | Экран анализа: чек-лист заполняется на глазах | Innovation |
| 1:05–1:40 | **Палец в цитату:** вот где вы не извинились | Innovation |
| 1:40–2:00 | CSV: N студентов, самый проваливаемый пункт | Validation |

**Кульминация — цитата, а не чат.** Если время горит, жертвуйте диалогом, но не экраном результата.

# 2. ДИЗАЙН

## 2.1 Принцип

**«Рабочий журнал практики», а не «AI-чат».**

Запрещено: тёмная тема, неоновые градиенты, фиолетовый, иконки-роботы, «звёздочки ИИ». Всё это мгновенно читается жюри как обёртка над GPT и бьёт по критерию «Инновационность».

## 2.2 Цвета

```css
--paper      #FBFAF7   /* фон страницы, тёплый, не белый */
--card       #FFFFFF
--ink        #1C1F26   /* основной текст */
--ink-soft   #5A6270   /* вторичный */
--line       #E5E2DB   /* границы, тёплый серый */
--brand      #1F4E5F   /* глубокий петролевый: кнопки, акценты */
--brand-soft #E8F0F2   /* фон блока цитаты */
--pass       #2E7D52
--fail       #B3402F
--warn       #A8681C
```

Петролевый вместо синего — синий занят всеми AI-продуктами.

## 2.3 Типографика и сетка

- **Один шрифт:** системный стек `-apple-system, "Segoe UI", Roboto, sans-serif`. **Без Google Fonts CDN** — на площадке может не быть интернета.
- Заголовок экрана 26/600 · карточки 18/600 · текст 16/1.55 · подпись 13/1.4.
- Реплики в диалоге — не мельче 16px: их читают со сцены.
- Шаг сетки 8px: 8 / 16 / 24 / 32 / 48. Внутри карточки 24, между карточками 16.
- Ширина контента **max 760px**, по центру.

## 2.4 Компоненты

- **Карточка:** белая, радиус 14, граница 1px `--line`, тень `0 1px 2px rgba(0,0,0,.04)`.
- **Кнопка основная:** заливка `--brand`, белый текст, радиус 10, паддинг 12/22.
- **Вторичная:** белая, граница и текст `--brand`. **Третья:** без границы, текст `--ink-soft`.
- **Поле ввода:** радиус 10, при фокусе граница `--brand` + кольцо `--brand-soft`.
- **Disabled:** `opacity .45` + `cursor: not-allowed`.

## 2.5 Диалог

- **Шапка сцены:** название ситуации и роль — «Вы: администратор стойки».
- **Реплика гостя:** слева, фон `--card`, цветная полоса 3px слева, подпись «Гость».
- **Реплика студента:** справа, заливка `--brand`, белый текст, подпись «Вы».
- **Прогресс:** 8 точек в шапке, пройденные закрашены. Даёт ощущение конечности.
- **Печатает:** три точки, волновая анимация 1.2s.
- Ширина реплики — максимум 78%.

## 2.6 Результат — главный экран

- **Шапка:** крупное «6 / 8», процент, шкала. Цвет: `--pass` от 70%, `--warn` от 40%, ниже `--fail`.
- **Пункт — карточка с левой границей 4px** цветом `--pass`/`--fail`. Список читается за 2 секунды боковым зрением.
- **Цитата — визуальный центр.** Фон `--brand-soft`, вертикальная линия слева, курсив, кавычки-ёлочки. **Заметнее комментария** — это и есть доказательство.
- Бейдж `--warn` «цитата не подтверждена», если её нет в расшифровке.
- **Невыполненные пункты — сверху.** Студент должен видеть зоны роста, а не похвалу.

## 2.7 Анимации

Сдержанно, каждая служит пониманию.

- Реплика: `fadeIn` + сдвиг 6px снизу, 180ms.
- Смена экрана: `fadeIn` 200ms. Без слайдов и переворотов.
- **Экран анализа:** пункты проступают с шагом 400ms — единственная постановочная анимация, оправдана тем, что показывает процесс оценки.
- Шкала: `transition: width 600ms ease-out`.
- Учесть `prefers-reduced-motion`.

# 3. АРХИТЕКТУРА

## 3.1 Структура проекта

```
/
├── index.html          ← весь фронтенд: HTML + CSS + JS в одном файле
├── api/
│   └── gemini.js       ← serverless-функция Vercel, держит ключ
├── .gitignore
└── MVP_MASTER_PLAN.md
```

**Три файла.** Ни package.json, ни сборки, ни фреймворка, ни node_modules. Vercel определяет статику и папку `api/` автоматически, без конфига.

## 3.2 Почему именно так

| Решение | Причина |
|---|---|
| Статический `index.html` | Открывается и локально, и на Vercel. Ноль сборки |
| Одна функция в `api/` | **Ключ на сервере.** Жюри открывает ссылку и пользуется, ключ им не нужен и в коде не виден |
| Без фреймворка | Экономия 1–2 часов и десятка точек отказа |
| Без `type="module"` | ES-модули ломаются при открытии через `file://` |
| Без БД | Сессия однопользовательская, хватает localStorage |

## 3.3 Serverless-функция `api/gemini.js`

Принимает POST, обращается к Gemini, возвращает текст. Логика:

1. Проверить `req.method === "POST"`, иначе 405.
2. Взять `process.env.GEMINI_API_KEY`. Нет — вернуть 500 с понятным текстом.
3. Принять из тела: `contents`, `system`, `generationConfig`.
4. **Перебрать список моделей по очереди**, пока одна не ответит успешно.
5. Вернуть `{ text, model }` или `{ error }` с текстом ошибки от Google.

**Перебор моделей обязателен.** Документация Google в переходном состоянии: `generateContent` помечен Legacy, имена Flash-моделей в разных разделах разные, а **на бесплатном тарифе у части моделей суточная квота равна нулю** — тогда 429 приходит на первый же запрос и ожидание не помогает. Перебор снимает и 404, и такой 429 автоматически.

```js
const MODELS = [
  "gemini-3.6-flash",
  "gemini-3.5-flash-lite",
  "gemini-flash-latest",
  "gemini-flash-lite-latest"
];
```

Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
Заголовок: `x-goog-api-key`.

**Если ни одна модель не ответила** — вернуть текст ошибки от последней попытки целиком, не подменять общей фразой. Иначе диагностика невозможна.

## 3.4 Два типа запросов

Функция одна, режим передаётся в теле.

| Режим | Назначение | temperature |
|---|---|---|
| `roleplay` | Модель играет гостя, получает всю историю | 0.9 |
| `assess` | Модель получает расшифровку и чек-лист, возвращает JSON | 0.2 |

Разделять обязательно: модель, только что игравшая роль, оценивает себя необъективно.

Для `assess` — `responseMimeType: "application/json"` и `responseSchema`.

## 3.5 Данные

```js
SCENARIO = { title, role, situation, task, rolePrompt,
             firstMessage, maxTurns, checklist:[{id, text}] }

history  = [{ role: "user"|"model", text }]

result   = { items:[{ id, text, passed, quote, fabricated, feedback }], summary }

session  = { at, turns, passed, total, demo, history, items, summary }
```

`SCENARIO` — одним объектом в начале скрипта, чтобы менять сценарий без правки логики.
Сессии — в `localStorage`, экспорт CSV с BOM `\uFEFF` для Excel.

## 3.6 Ключи и переменные окружения

| Где | Статус |
|---|---|
| `GEMINI_API_KEY` в переменных Vercel | ✅ единственное место |
| В `index.html` | ❌ никогда |
| В git | ❌ никогда |

**Защита от слива квоты.** Публичная ссылка с вашим ключом — любой может сжечь бесплатный лимит. Добавить в функцию проверку `process.env.ACCESS_CODE`: если переменная задана, фронтенд шлёт код в заголовке. Код вшить в `index.html` константой — от случайных ботов защищает, от целенаправленного взлома нет, и на хакатоне этого достаточно.

## 3.7 Ошибки

Показывать текст от Google, а не только код:

| Код | Сообщение |
|---|---|
| 400 | Запрос отклонён |
| 403 | Ключ недействителен — проверьте переменную на Vercel |
| 404/429 | Обрабатывается перебором моделей автоматически |
| 5xx | Сбой Google, повторите через минуту |
| Нет сети | Включите Demo-режим |

**Парсинг JSON оценки — три уровня:**

1. Запрос с `responseSchema`.
2. При отказе — повтор без схемы с текстовой инструкцией вернуть чистый JSON.
3. Парсер срезает обёртку ```` ```json ````, при неудаче берёт подстроку от первой `{` до последней `}`.
4. `normalize()` достраивает недостающие пункты из `SCENARIO.checklist`, чтобы таблица не разъезжалась.

## 3.8 Demo-режим

Захардкоженный объект с историей и готовой оценкой, отрисовывается **тем же кодом**, что и живой результат. Работает без сети. Перед демо заменить на свой лучший реальный прогон.

## 3.9 Деплой

**Vercel, через CLI, прямо из IDE.**

```bash
npm i -g vercel          # один раз
vercel login             # один раз, вход по email
vercel                   # первый деплой, создаёт проект
vercel env add GEMINI_API_KEY production
vercel --prod            # публикация
```

Ключ получить на `aistudio.google.com` → Get API key. Карта не нужна, бесплатный тариф бессрочный.

**Локальная проверка:** `vercel dev` поднимает статику и функции на `localhost:3000`. Открывать `index.html` двойным кликом после Фазы 1 нельзя — функции не запустятся.

**После каждого изменения:** `vercel --prod`.

## 3.10 Что НЕ строить

| Не делаем | Почему |
|---|---|
| База данных, авторизация | Нет сценария, требующего их |
| React, Vue, сборка | Часы настройки и новые точки отказа |
| Несколько сценариев | Один отработанный сильнее трёх сырых |
| Голосовой ввод | Web Speech API нестабилен, казахский почти не поддерживает |
| Загрузка DOCX/PDF | Типичная потеря двух часов |
| Кабинет преподавателя | Показать слайдом как следующий шаг |
| Адаптив под телефоны | Демо с ноутбука. Хватит `max-width` и переноса кнопок |

# 4. ROADMAP — 4 ФАЗЫ

### ФАЗА 1 — Каркас, дизайн-система, деплой

- **Цель:** живая ссылка на Vercel, где работает запрос к модели.
- **Что сделать:** `index.html` с палитрой 2.2, типографикой 2.3, компонентами 2.4; пять секций с классом `hidden` и функция `show(name)`; `api/gemini.js` с перебором моделей; `.gitignore`; деплой на Vercel; переменная `GEMINI_API_KEY`.

- **Готово когда:** тест проходит **на опубликованной ссылке**, не только локально. Если ни одна модель не отвечает — остановиться и решать здесь.

# 6. ФИНАЛЬНАЯ ПРОВЕРКА

**PRODUCT** — путь «сценарий → диалог → анализ → результат» проходится без ошибок; чек-лист показан до диалога; «Пройти заново» работает.

**DESIGN** — пять экранов в одной стилистике, цвета только из палитры 2.2; не похоже на AI-чат; шрифт не с внешнего CDN; текст читается с 2 метров.

**AI** — роль держится 5+ реплик; модель помнит детали; реагирует на качество ответов.

**ASSESSMENT** — все 8 пунктов заполнены; **каждая цитата есть в расшифровке**; комментарий конкретен; плохой диалог получает низкую оценку.

**RELIABILITY** — перебор моделей снимает 404/429; кривой JSON не роняет приложение; Demo-режим работает без сети.

**SECURITY** — ключ только в переменных Vercel; в `index.html` и git его нет; `ACCESS_CODE` включён.

**DEMO** — 3 прогона подряд; записан свой лучший прогон в `DEMO`; укладываетесь в 2 минуты; есть план на отказ сети.

**DEPLOYMENT** — ссылка открывается на чужом устройстве без установок и ключей.

## 6.1 Связь с критериями VentureHack

| Критерий | Чем закрываем | Где |
|---|---|---|
| **Problem & Impact (20)** | Реальная ситуация с практики, цифры по нехватке мест практики, цитаты преподавателя | Экран сценария + слайд 1 |
| **Innovation (20)** | Оценка по профстандарту **с дословными цитатами**, а не текстовый отзыв. Чат этого структурно не даёт | Экраны анализа и результата |
| **Technical Execution (25)** | Сквозной сценарий без заглушек, serverless-прокси, `responseSchema`, трёхуровневый парсинг, сверка цитат, demo-режим | Фазы 1–4 |
| **Feasibility (15)** | Работающая публичная ссылка, себестоимость запроса, канал через преподавателя | Ссылка Vercel + слайд |
| **Validation (10)** | CSV с прогонами студентов; сравнение оценки ИИ с оценкой преподавателя вслепую | Фаза 4 + тест на людях |

## 6.2 Главный риск — не технический

Код собирается за 4–6 часов. **Проект проигрывает не из-за кода, а из-за отсутствия данных.**

Без 5–10 пройденных студентами сессий и без оценки преподавателя теряются баллы за Problem & Impact и Validation — **30 из 100**. Это больше, чем стоит любая доработка интерфейса.
